# 高保真还原与自动校正方案

> 目标：在快速生成首版代码的同时，尽可能还原原图，并通过自动检测和增量修复持续提升质量。

## 1. 核心原则

1. **快速预览与质量校验解耦**：用户先看到草稿，后台继续校正。
2. **不能只看整图像素相似度**：大面积空白会掩盖缺失文字和组件。
3. **每次修复只修改差异区域**：避免全量重新生成导致速度变慢和引入新差异。
4. **每轮修复必须重新渲染验证**：没有重新验证的修复不能视为完成。
5. **达到阈值提前结束，连续无改善立即停止**：避免无效模型调用。
6. **保留人工审核入口**：复杂交互和业务语义不能仅靠图片推断。

## 2. 完整质量闭环

```text
原图 → 快速生成草稿 → 按原图尺寸渲染
                    ↓
          多维度质量检测与评分
                    ↓
        生成差异区域和结构化问题清单
                    ↓
       VL 对比原图/结果图/差异图并定位原因
                    ↓
       基于当前代码生成最小范围修复操作
                    ↓
          应用修复 → 重新渲染 → 再评分
                    ↓
       达标 / 无改善 / 达到轮次上限 → 输出报告
```

## 3. 多维度质量评价

建议使用可配置的综合评分，而不是只返回 Pixelmatch 百分比。

| 维度 | 检测内容 | 推荐权重 |
| --- | --- | --- |
| 像素与边缘 | 颜色、边界、图片、主要视觉差异 | 35% |
| 布局与区域 | 区域位置、尺寸、间距、对齐、缺失区域 | 25% |
| 文字完整性 | 标题、按钮、正文、数字是否缺失或错误 | 20% |
| 样式一致性 | 字体、字号、字重、圆角、阴影、Design Token | 20% |

权重只是初始建议，应通过实际测试集调整。

### 3.1 内容遮罩

计算像素分数时，应同时提供：

- 整图相似度；
- 内容区域相似度；
- 空白区域占比；
- 最大单一差异区域占比。

防止“背景基本相同，但重要内容缺失”仍获得高分。

### 3.2 区域差异

当前固定 100×100 网格只能用于初步定位。后续应使用：

- 差异连通区域合并；
- 原图与结果图的边缘图对比；
- 区域边界框对齐误差；
- Header/Main/Sidebar/Footer 等语义区域映射。

### 3.3 文字检查

至少检查：

- 原图中的标题是否出现在结果中；
- 按钮文字、关键数字、导航项是否缺失；
- 是否出现原图没有的额外内容；
- 文本是否被截断或意外换行。

中文场景可使用 OCR，或由 VL 在独立审查请求中输出文字差异清单。OCR 结果不应作为唯一依据。

## 4. 自动修复策略

### 4.1 结构化问题清单

每个问题包含：

```json
{
  "type": "missing_text|position|size|color|typography|spacing|asset|extra_content",
  "region": { "x": 100, "y": 200, "width": 320, "height": 80 },
  "expected": "原图中的预期表现",
  "actual": "当前渲染的实际表现",
  "severity": "critical|major|minor",
  "confidence": 0.92
}
```

### 4.2 修复输入

修复模型需要同时获得：

- 原图；
- 当前渲染图；
- 差异图；
- 结构化问题清单；
- 当前文件路径和当前代码；
- 项目 Design Token 和组件约束。

使用独立审查上下文，避免模型仅根据先前假设自我确认。

### 4.3 最小修改

优先使用局部编辑：

```json
{
  "edits": [
    {
      "oldText": "需要替换的现有代码片段",
      "newText": "修复后的代码片段",
      "reason": "修复标题字号和间距"
    }
  ]
}
```

禁止在局部修复时：

- 无必要地改变组件结构；
- 重写无关区域；
- 修改已确认的数据接口；
- 为追求像素分数把整页替换成一张图片。

## 5. 质量档位

| 档位 | 首版预览 | 自动校正 | 适用场景 |
| --- | --- | --- | --- |
| 快速 | 立即显示 | 后台最多 1 轮 | 草稿、原型 |
| 均衡（默认） | 立即显示 | 最多 2-3 轮 | 日常页面开发 |
| 精确 | 立即显示 | 多轮直到阈值或无改善 | 重要页面、设计验收 |

每轮只处理高优先级差异，低优先级抗锯齿和字体渲染噪声应被过滤。

## 6. 停止条件

满足任一条件即停止：

1. 综合评分达到目标，且不存在关键文字或组件缺失；
2. 连续两轮综合评分改善小于设定值；
3. 达到最大修复轮次；
4. 模型无法产生有效局部编辑；
5. 页面需要业务逻辑或交互信息，图片无法提供。

最终结果必须标记为：

- `passed`：自动校验通过；
- `needs_review`：仍需人工审核；
- `failed`：自动修复失败。

## 7. 与现有项目的结合

| 模块 | 建议 |
| --- | --- |
| `src/validator/visual-validator.ts` | 拆分渲染、像素对比、区域分析和评分 |
| `src/prompts/` | 新增视觉审查与局部修复 Prompt |
| `src/index.ts` | 增加有界自动校正循环 |
| `src/server/job-service.ts` | 保存每轮报告、代码版本和截图 |
| `src/mcp/server.ts` | 暴露质量报告和修复状态，不只返回最终代码 |
| `test/` | 增加合成图片和真实页面的质量回归测试 |

建议产物结构：

```text
jobs/<job-id>/
├── source.png
├── current/当前代码
├── iterations/每轮代码、截图和差异
├── quality-report.json
└── final/最终代码与报告
```

## 8. 测试与验收

必须加入以下测试：

- 相同图片应接近满分；
- 缺少按钮文字不能被判定为通过；
- 卡片整体移位应被区域指标捕获；
- 主色错误应被样式指标捕获；
- 大面积空白但缺少内容不能获得虚假高分；
- 修复后变差时应停止或回滚到上一轮；
- 多次修复不得修改无关代码；
- 移动端和桌面端分别使用正确的原始视口。

最终验收同时关注：

- 综合质量分；
- 关键内容完整率；
- 自动修复成功率；
- 平均修复轮次；
- 总耗时和首个预览时间；
- 人工审核发现的问题数量。

## 9. 实施顺序

1. 先拆分质量指标，消除单一像素分数的误导。
2. 再实现区域问题清单和独立视觉审查。
3. 接入基于当前代码的局部修复。
4. 增加有界校正循环、回滚和质量报告。
5. 最后与快速预览结合，后台自动完成质量提升。

这样可以在不明显牺牲首版速度的前提下，提高还原度，并让系统自动识别和校正问题，而不是只报告一个相似度数字。
