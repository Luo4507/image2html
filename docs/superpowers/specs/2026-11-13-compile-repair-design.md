# 编译失败自动修复设计

**日期：** 2026-11-13

## 目标

React/Vue 生成源码在类型检查、Vite 构建或浏览器挂载失败时，先使用错误诊断修复源码，再执行原有视觉校验，不再直接终止整个转换。

## 流程

1. 首次校验抛出框架运行错误时，保留当前源码、文件名、资源和模型计数。
2. `qualityMode` 为 fast 或 `maxRetryCount=0` 时不修复；balanced/precision 默认最多修复一次。
3. 将目标选项、当前完整源码和精简诊断交给代码模型，要求返回完整修复源码。
4. 修复后重新执行类型检查、Vite 构建和 Playwright 渲染；失败则保留最后源码并返回最后一次诊断。
5. 只有成功渲染后才计算与原图的相似度，并进入现有视觉修复流程。
6. `repairIterations` 统计编译与视觉修复总次数，结果新增编译修复历史，记录每次诊断和是否恢复。

## 边界

- HTML 不使用该模型修复流程。
- 不放宽 TypeScript 规则，不伪造不存在依赖，不忽略浏览器运行错误。
- 修复模型只返回源码，不执行其生成的命令。
- 失败结果继续保留最后源码和指标，保证可审计。

## 回测

使用掘金回测中已保存的 React/Vue 失败源码和真实诊断直接调用修复接口，再与原图进行真实渲染和像素比较。分别记录修复是否成功、编译诊断、相似度和质量门禁。
