# 生成流程资源接入设计

**日期：** 2026-11-13
**状态：** 按已批准的第五阶段顺序实施

## 目标

将现有视觉模型资源检测与裁剪能力接入转换流程，使生成代码能够引用实际提取的 Logo、图标和图片，并在 HTML/React/Vue 校验与完整工程导出中使用同一份资源。

## 方案

- `CodegenOptions` 新增 `assetMode: 'none' | 'extract'`，默认 `none`，避免现有转换额外调用模型。
- `extract` 模式在代码生成前调用现有资源提取器，读取裁剪结果为内存中的 `GeneratedAsset`，资源提取计一次模型调用。
- 生成提示词附带允许使用的 `/assets/<filename>` 清单；模型只能选择清单内资源，不得编造路径。
- `GeneratedCode` 保存资源名称、MIME 和 base64 内容。失败结果同样保留已生成源码和资源。
- React/Vue 的临时 Vite 工程和导出工程将资源写入 `public/assets`。
- HTML 继续使用 `page.setContent()`，校验时仅把资源引用替换为 data URL；磁盘工程仍使用 `/assets` 路径。
- CLI 提供 `--extract-assets`。MCP/HTTP 参数统一在下一独立任务处理。

## 安全与可靠性

- 资源文件名只保留 basename，并限制为字母、数字、点、下划线和连字符；冲突名称追加稳定序号。
- 不执行资源内容，不请求外部 URL，不写入模型提供的目录。
- 临时裁剪目录在读取后删除；Vite 服务关闭后继续沿用现有清理。
- 无资源时继续生成，资源清单为空，不因“未检测到图片”失败。

## 测试与完成标准

- 单元测试覆盖资源清单、文件名清理、转换模型调用计数和失败产物。
- 导出测试证明 `public/assets` 中的字节与裁剪结果一致。
- React 固定组件通过 `/assets` 加载真实图片，浏览器断言 `naturalWidth > 0`。
- HTML 使用资源前后进行像素比较，证明校验能读取资源。
- 全套测试、类型检查、构建和一次 `extract` 模式真实图片回测通过；视觉门禁结果单独报告。
