# 渲染等待与小区域修复优化

**日期：** 2026-11-13

## 目标

消除 React 页面 networkidle 超时和 Vue 小区域裁剪导致的模型 HTTP 400，同时保持诊断准确和异常可恢复。

## 设计

- Vite 页面使用 domcontentloaded，再检查根节点、字体和首帧；超时但已挂载的页面允许继续并记录警告。
- 布局诊断增加 pending/failed 请求，便于区分服务、资源和脚本问题。
- 修复区域以中心向外扩展到至少 16×16，受原图边界约束，不拉伸差异区域本身。
- 小于 16px 的原图补白到 16px，确保模型输入满足接口限制。
- 添加慢资源、已挂载超时和 1px 边缘区域回归测试。

## 验证

分别重跑掘金 React 和电鸭 Vue，保存真实渲染、原图差异、质量指标和错误记录。全量测试、类型检查、构建通过后合入并推送 master。

## 完成结果

- 30 个测试文件、87 项测试全部通过，类型检查和生产构建通过。
- 掘金 React 完成编译修复、浏览器渲染和原图对比，不再出现 networkidle 超时。
- 电鸭 Vue 的区域裁剪满足模型输入要求，视觉修复和原图对比完成，不再出现 HTTP 400。
- 实际相似度：掘金 React 79.12%，电鸭 Vue 93.20%；严格视觉质量门禁均未通过。
