# 视觉一致性分阶段改进设计

**日期：** 2026-11-13

## 目标

在不放宽现有内容/边缘质量门禁的前提下，提高 HTML、React、Vue 的真实视觉一致性，并保证测量准确、修复可回滚、长页面不截断。

## 阶段一：尺寸与像素比较

- 保持原图尺寸作为比较画布，不再把不同宽高的渲染图强制拉伸到原图。
- 超出原图的内容裁剪，不足部分使用白色补白；分别记录原图与渲染图宽高及差值。
- 主校验继续使用原图尺寸视口；保存实际 full-page 尺寸用于诊断。

## 阶段二：DOM 几何和计算样式诊断

- 渲染时采集主要语义元素、交互元素、图片和 data-testid 元素的边界框。
- 采集颜色、背景、字体、字重、padding、margin、gap 和圆角等计算样式。
- 将精简后的布局快照随校验结果和视觉修复提示词传递。

## 阶段三：区域修复与可靠回退

- 每轮优先选择差异像素最多的区域，向视觉模型提供原图、渲染图和差异图的对应裁剪。
- 保留精确补丁路径；补丁定位失败时，使用同一视觉上下文生成完整候选源码。
- 完整候选必须经过构建和视觉评分，只有改善才被采用；记录实际模型调用。
- 编译修复保持最小修改原则，视觉修复始终携带原图约束。

## 阶段四：React/Vue 长页面分段生成

- 复用现有区域规划和裁剪。
- React 区域生成带唯一导出的组件，组合为一个默认导出页面。
- Vue 区域生成合法 SFC 片段，组合 template、script setup 和 style。
- 分段结果继续使用相同 Vite 构建、视觉校验和修复流程。

## 阶段五：真实回测

- 使用掘金和电鸭分别回测 HTML、React、Vue。
- 记录尺寸差异、内容/边缘指标、修复历史和模型调用。
- 对长页面补充分段生成验证；逐张串行检查渲染与差异图。

## 完成标准

像素比较不经过非等比拉伸；布局诊断可审计；无效补丁有视觉约束的候选回退且不会采纳退化版本；React/Vue 分段代码可构建；真实结果无论门禁是否通过都如实报告。
