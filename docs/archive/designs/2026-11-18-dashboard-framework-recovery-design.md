# Dashboard React/Vue 编译与挂载修复设计

**日期：** 2026-11-18

## 背景

2026-11-15 的 Dashboard 真实回测中，React 和 Vue 都在一次模型修复后仍然失败：

- React：项目使用 Ant Design 5.0.0，生成源码却使用当前版本不支持的 `Breadcrumb.items`，最终类型检查失败。
- Vue：生成源码使用 `<el-*>` 全局组件，但工程入口只加载 Element Plus 样式，没有注册组件；现有错误仅报告 `#root is empty after mount`，不足以单独证明挂载失败的直接原因。

本批次只处理框架代码的编译、构建、浏览器挂载和诊断可靠性。视觉相似度提升、回测集去重和性能优化属于后续批次。

## 目标

1. 让直接生成和编译修复共同遵守项目实际安装的组件库 API。
2. 让使用 Element Plus 全局组件写法的 Vue SFC 能在校验工程与导出工程中一致运行。
3. 空挂载失败时保留足够的浏览器诊断，便于定位直接原因。
4. 用自动化回归和 Dashboard 真实模型重跑验证修复，而不是只验证手工修改后的产物。

## 非目标

- 不升级 Ant Design、Element Plus 或其他依赖版本。
- 不引入 TSX/Vue SFC 字符串补丁或自动代码转换器。
- 不调整整图、内容、边缘或文本质量门禁。
- 不要求 Dashboard 的真实生成结果在本批次通过视觉质量门禁。
- 不修改其他示例的生成结果，不开展全量视觉调优。

## 方案

### 1. 共享组件库生成契约

提取一个小型共享提示词契约，由直接生成与编译修复共同使用，避免两条路径对组件库 API 的描述不一致。

React + Ant Design 契约至少明确：

- 当前运行时为 Ant Design 5.0.0。
- `Breadcrumb` 使用 `<Breadcrumb><Breadcrumb.Item>...</Breadcrumb.Item></Breadcrumb>`，不得使用 `items` 属性。
- 继续使用现有图标白名单，不扩大依赖范围。

其他 React 组件和无组件库模式保持现有行为。编译修复仍需保留页面结构、文字、样式和资源引用，不得通过删除页面或放宽 TypeScript 配置规避错误。

### 2. Vue Element Plus 入口注册

当且仅当 `framework === "vue"` 且 `componentLibrary === "element"` 时，工程入口：

- 默认导入 `ElementPlus`；
- 保留现有 `element-plus/dist/index.css` 样式导入；
- 使用 `createApp(Component).use(ElementPlus).mount('#root')`。

校验临时工程和用户导出的工程继续复用 `createFrameworkProjectFiles()`，因此只需修改统一入口模板。显式导入 Element Plus 组件的 SFC 仍可运行；无组件库的 Vue 工程不增加 Element Plus 导入或注册。

### 3. 空挂载浏览器诊断

框架页面渲染期间继续优先收集并抛出 `pageerror`。另外收集有界的浏览器 `console` 错误与警告，用于 `#root` 为空时的错误消息：

- 最多保留 20 条，每条最多 500 个字符，避免大型日志淹没诊断；
- 仅在空挂载失败时将诊断附加到错误；
- 已存在 `pageerror` 时保持当前优先行为；
- 不把普通警告直接视为转换失败。

这样 Vue 全局组件缺失、资源异常和其他挂载问题能留下可操作的证据，同时不改变成功页面的门禁逻辑。

## 数据流

1. 直接生成或编译修复通过共享组件库契约生成完整源码。
2. `createFrameworkProjectFiles()` 创建统一的 React/Vue 临时工程。
3. Vue + Element Plus 的入口注册组件库后再挂载页面。
4. Vite 类型检查和生产构建仍先于浏览器校验。
5. 浏览器出现运行异常或空挂载时，错误携带分阶段诊断并进入现有编译修复流程。
6. 成功挂载后才继续截图、像素比较和视觉质量门禁。

## 测试策略

遵循测试先行，每项实现前先添加能暴露当前缺口的测试：

1. **提示词测试**：直接生成与编译修复都包含 Ant Design 5.0.0 的 `Breadcrumb` 子节点契约，并明确禁止 `items`。
2. **工程模板测试**：Vue + Element Plus 入口包含默认导入、样式和 `.use(ElementPlus)`；其他 Vue 配置不注册组件库。
3. **React 真实运行时回归**：使用 Ant Design 5.0.0 兼容的 `Breadcrumb.Item` 页面完成类型检查、构建和浏览器文本渲染。
4. **Vue 真实运行时回归**：不显式导入 Element Plus 组件、只使用 `<el-*>` 全局标签的 SFC 能构建并在 `#root` 渲染可见文本。
5. **诊断回归**：没有运行异常但根节点为空时，错误包含收集到的关键浏览器警告；普通成功页面不受警告收集影响。
6. **全量回归**：类型检查、所有 Vitest 测试和生产构建全部通过。

## React 配色与侧边栏对比度修复

真实产物与浏览器计算样式证明，Ant Design 的组件默认样式会覆盖普通 Tailwind 背景类；默认 `Menu` 和 `Typography` 文字颜色也不适合暗色侧边栏。仅修改当前产物中的 `!bg-white` 与 `theme="dark"` 后，对照实验的相似度由 89.67% 提升到 94.06%，质量分由 71.88 提升到 75.93，验证了这两处根因。

随后将以下契约接入直接生成、编译修复、视觉补丁和完整视觉修复，并在视觉修复调用中传入实际框架配置：

- 浅色 `Layout.Header` 使用 `!bg-white` 或等价内联背景，避免默认深色覆盖。
- 暗色侧边栏的 `Menu` 显式使用 `theme="dark"`。
- 暗色侧边栏中的 `Typography` 品牌标题和文字显式使用 `!text-white` 或设计稿对应的浅色。

当前离线验证为 31 个测试文件、95 项测试全部通过，TypeScript 类型检查、生产构建和 CLI 检查通过。真实 Vite 运行时回归同时断言顶栏计算背景为白色、菜单具有暗色主题。
